# Scheduling, queues, and alternative times

After advisor approval, eligible requests enter the scheduling workflow. The system considers existing reservations and available resources; it does not assume that an apparently idle GPU can be claimed.

## Common outcomes

| Status or situation | What it means | What the student should do |
| --- | --- | --- |
| Awaiting advisor | No advisor decision recorded | Ask the advisor to review the ticket |
| Awaiting scheduler | Eligible request awaits scheduling feedback | Retain the ticket and check status |
| Queued | Requested time or resources cannot currently be allocated | Stay queued or revise within permitted limits |
| Alternative window suggested | A possible different slot was identified | Accept or propose a permitted revision; the suggestion is not guaranteed |
| Requested time has passed | The original booking window can no longer be used | Choose a future window and obtain a fresh availability check |
| Needs correction | Request details failed a validation or policy check | Correct the details through the authorized process |
| Scheduled / allocated | Reservation created in the GPU Panel | Follow the confirmation and authorized usage scope |

Students can generally retain advisor approval when changing **only the time and/or reducing resources or duration** within the previously approved limits. A material increase, changed research purpose, changed advisor, or specialized risk requires new review. Changes must be rechecked before a booking can be confirmed.

The scheduler does not retroactively create a reservation for a time window that has already passed.
